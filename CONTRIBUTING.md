# Contributing

## Developer Certificate of Origin

Every commit must be signed off under the Developer Certificate of Origin 1.1:

```bash
git commit -s
```

The sign-off certifies that you have the right to submit the contribution under the project's license. Contributions without a matching `Signed-off-by` trailer are rejected by review.

Commits must also be cryptographically signed when the contributor has signing configured:

```bash
git commit -S -s
```

## Setup

```bash
npm --prefix apps/desktop ci
cargo build --workspace
```

The desktop application expects macOS 13 or newer and the Xcode command line tools.

## Before opening a pull request

Run the same gate as CI:

```bash
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo deny check
npm --prefix apps/desktop run typecheck
npm --prefix apps/desktop run build
```

For release candidates, build the auditable binary:

```bash
cargo install cargo-auditable
cargo auditable build --release -p slabbase-desktop
otool -l target/release/slabbase-desktop | grep dep-v0
```

If you changed Rust types that cross the IPC boundary, regenerate the TypeScript bindings:

```bash
cargo test -p slab-core --features ts
```

The generated files live in `apps/desktop/src/bindings` and are committed. Do not edit them by hand.

### CI on pull requests

Every push to a pull request runs a quick Ubuntu check (`cargo fmt --check` and the frontend typecheck) and the JavaScript CodeQL analysis. The macOS gates (Rust gate, desktop UI audit shards, bundle check, and Rust CodeQL) run only when the pull request has the `ok-to-test` label, so review-driven pushes do not each start a full macOS run. Add the label when the branch is ready for full verification; every later push re-runs the macOS gates while the label stays on. `CI gate` is the required check: it fails until the label is present and Quick check, Rust gate, every desktop shard, Bundle check, and Rust CodeQL have passed. Removing the label re-runs CI on the same commit, so `CI gate` fails again rather than letting skipped jobs stand in for earlier results.

## Commit style

Conventional Commits, imperative mood, subject under 55 characters, one logical change per commit. Examples:

```text
feat(core): add exact currency rounding
fix(storage): keep cursors stable on null sort keys
docs: describe audit log retention
```

Do not add co-author trailers. Do not add tool attribution to commits, code, comments, or documentation.

## Code standards

- `slab-core` and `slab-formula` must not gain filesystem, network, SQLite, or UI dependencies.
- Shipping code must not call `unwrap`, `expect`, or `panic`. Return a typed error with a stable `SLAB_E_*` code.
- Public functions take borrowed parameters when ownership is not required.
- New behavior needs a test. Bug fixes need a regression test.
- Keep user-visible strings factual. Avoid marketing language in the product and in the docs.

## Workspace files

Do not commit personal `.slab` workspaces. The `fixtures/` directory is the only place for sample databases, and it is generated by the seed code.
